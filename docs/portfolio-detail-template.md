# 포트폴리오 상세페이지 공통 구성

첫 적용: `/projects/online-prepay`. 다른 프로젝트 상세페이지는 기존 구성을 유지합니다.

## 편집 기준

1. **첫 화면**: 프로젝트 이름, 해결하는 문제 한 문장, 이용 대상, 현재 상태, 실제 사이트 링크.
2. **기기 목업**: 실제 PC 캡처와 모바일 화면. 재구성한 UI는 실제 캡처와 구분해 표시.
3. **만든 이유**: 현장 불편 2~3개, 관련 사진, 프로젝트가 풀려는 질문.
4. **해결 방식**: 문제와 기능을 연결하는 간단한 시각 요소.
5. **화면 설계**: 실제 화면 일부와 번호를 연결해 핵심 기능 3개 설명.
6. **사용 방법**: 3~5단계, 입력 예시와 결과 화면. 필요한 경우 작은 체험 요소.
7. **제작 과정**: 관찰 → 설계 → 구현 → 개선. 실제 기록에 있는 과정만 기술.
8. **현재 범위와 다음 단계**: 구현/모의 기능/계획을 구분하고 실제 사이트 CTA로 마무리.

## 이미지 공통 원칙

- 프로젝트의 색상, 분위기, 사용 상황과 맞는 고화질 이미지를 직접 선정합니다.
- 기능 설명의 주인공은 실제 서비스 화면입니다. 사진은 사용 맥락을 보완합니다.
- 기기 목업은 CSS 프레임으로 제작해 크기 변화에도 선명하게 표시합니다.
- 선결제 샘플의 모바일 목업은 실제 서비스 iframe입니다. 서비스 운영 도메인의 임베드 정책 변경 시 정적 모바일 캡처로 교체해야 합니다.
- 본문 이미지에는 의미 있는 대체 텍스트를 제공하고, 참고 사진을 실제 가게/고객 사진처럼 소개하지 않습니다.
- 출처와 사용 조건을 기록하며, 임의의 Behance 화면을 복제하거나 콘텐츠 이미지로 재사용하지 않습니다.
- 본문과 안내는 최소 16px, 출처 등 하단 보조 정보는 14px입니다.
- 단일 긴 이미지로 페이지 전체를 만들지 않습니다. 텍스트와 사용 단계는 반응형 HTML로 유지합니다.

## 참고한 구성

- [Daily Basket](https://www.behance.net/gallery/255267481/Daily-Basket-Grocery-App-UX-UI): 기기 목업, 문제·해결 설명, 기능별 UI 소개.
- [Talkie](https://www.behance.net/gallery/177296223/Talkie-Language-Learning-app-UI-UX-case-study): 큰 제목과 장면 전환, 화면에 붙이는 설명, 디자인 과정.
- [Prizo](https://www.behance.net/gallery/255372875/Prizo-Grocery-Price-comparison-App): 사용 흐름, 기획·제작 과정, 기능과 목적의 연결.

참고작의 시각적 설명 방식을 가영이네의 흰색·검정·오렌지 스타일로 재해석했습니다. 수행하지 않은 리서치, 가상의 성과 수치, 미연동 결제 기능을 추가하지 않습니다.

## 편집 위치

- 섹션과 설명: `components/PrepayCaseStudy.tsx`
- 반응형 스타일: `components/PrepayCaseStudy.module.css`
- 적립 계산 예시: `components/PrepayAmountDemo.tsx`
- 제목·사이트 URL·공개 상태: 기존 프로젝트 데이터 경로 유지

현재 샘플의 확장 섹션은 코드로 편집합니다. 기존 관리자 폼에 새 섹션 편집 기능이 추가된 것은 아닙니다. 전체 프로젝트에 확장할 때 섹션별 콘텐츠와 이미지 필드를 데이터 모델로 옮길 수 있습니다.
