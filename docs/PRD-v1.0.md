## 1. 제품 목적

이 사이트는 박가영의 개인적인 성장과 실행을 기록하고 공유하기 위한 포트폴리오다. 방문자가 “외식업 사장님도 현장의 문제를 발견하고 AI로 직접 도구를 만들 수 있구나”라고 이해하게 만드는 것이 핵심이다.

완성된 화면의 시각적인 매력과 함께, 어떤 불편에서 출발했고 무엇을 직접 만들었는지 쉽게 전달한다. 작품의 개수보다 실제 맥락, 제작 과정, 확인할 수 있는 결과를 중요하게 다룬다.

### 주요 방문자

| 대상 | 방문자가 궁금해하는 것 | 사이트가 제공할 내용 |
|---|---|---|
| 배달의민족 배민아카데미 관계자 | 외식업 현장에서 AI를 활용한 구체적인 사례와 실행 과정 | 제작 배경, 실제 화면, 구현 범위, 학습·개선 기록 |
| 외식업 사장님 | 우리 가게에도 비슷하게 적용할 수 있는지 | 쉬운 문제 설명, 사용 흐름, 직접 볼 수 있는 사이트 |
| 박가영의 활동에 관심 있는 방문자 | 어떤 사람이며 무엇을 만들어 왔는지 | 짧은 자기소개와 프로젝트 모음 |

### 기대하는 방문 흐름

1. 첫 화면에서 박가영이 외식업 사장님이자 AI 활용 제작자라는 것을 이해한다.
2. 썸네일을 보고 관심 있는 프로젝트를 발견한다.
3. 바로 아래 실제 화면 캡처로 결과물을 확인한다.
4. 상세 페이지에서 제작 이유와 과정을 읽는다.
5. 공개된 실제 사이트를 열거나 인스타그램에서 기록을 이어서 본다.

초기 목적은 사례 공유와 개인 기록이다. 개발 대행 판매, 채용 지원용 이력서, 사용자 간 작품 공유 플랫폼은 이번 범위에 포함하지 않는다.

## 3. 초기 출시 범위

### 필수 구현

- 메인 페이지: 소개, 프로젝트 갤러리, 짧은 자기소개, 외부 채널 링크.
- 5개 프로젝트 카드와 프로젝트별 상세 페이지.
- 각 카드의 디자인 썸네일과 **그 아래 별도로 배치되는 실제 사이트 캡처**.
- 실제 캡처 확대 보기.
- 실제 프로젝트 사이트로 이동하는 링크와 접근 상태 안내.
- 웹·모바일 반응형 레이아웃 및 키보드 조작.
- 프로젝트마다 공유할 수 있는 상세 URL과 기본 검색·공유 메타 정보.

### 후속 검토

- 프로젝트가 늘어난 뒤 카테고리 필터·검색.
- 별도 제작 일지와 시간순 업데이트 기록.
- 프로젝트 추가를 쉽게 하는 관리자 화면 또는 CMS.
- 실제 사용 후기, 검증된 이용 수치, 강의·발표 이력.

### 이번 범위에서 제외

- 회원가입, 로그인, 좋아요, 댓글, 팔로우 기능.
- 결제, 견적 요청, 개발 대행 신청 기능.
- 포트폴리오 내부에서 실행하는 챗봇이나 AI 생성 기능.
- 별도 모바일 앱과 비공개 업무 운영센터의 내부 정보 공개.
- 기존 5개 프로젝트 자체의 기능 개선·재개발.
- 프로토타입 검토용 A/B 전환 버튼과 PC/모바일 미리보기 전환 버튼.

## 4. 정보 구조

| 화면 | 주소 제안 | 주요 내용 |
|---|---|---|
| 홈 | `/` | 헤더, 소개, 5개 프로젝트, 자기소개, 푸터 |
| 프로젝트 상세 | `/projects/{slug}` | 제작 배경, 썸네일·실제 화면, 사용 흐름, 제작 과정, 구현 상태, 외부 링크 |
| 캡처 확대 | 상세 또는 홈 위 확대 대화상자 | 실제 캡처 확대, 닫기, 필요 시 이미지 영역 스크롤 |

주소는 구현을 위한 제안이다. 홈과 프로젝트 상세는 직접 URL로 진입하거나 새로고침해도 정상적으로 보여야 한다. 캡처 확대에 별도 URL은 필수가 아니다.

헤더에는 사이트명과 `프로젝트`, `소개` 이동 항목을 배치한다. 홈에서는 해당 구역으로 이동하고, 상세에서는 홈의 해당 구역으로 이동한다. 푸터에는 사이트명, 박가영, 인스타그램 링크를 배치한다.

## 5. 홈 화면 요구사항

### 5.1 헤더

- 블랙 배경 위에 읽기 쉬운 밝은 글자를 사용한다.
- 사이트명을 선택하면 홈으로 이동한다.
- 모바일에서는 사이트명과 핵심 메뉴가 화면 너비 안에 들어가도록 구성한다.
- 메뉴가 적으므로 복잡한 전체 화면 내비게이션은 필요하지 않다.

### 5.2 첫 화면 소개

첫 화면의 중심은 박가영의 정체성과 작업의 이유다. 소개문이 프로젝트 목록을 과도하게 아래로 밀어내지 않도록 한다.

**초기 적용 문구**

> 가영이네 AI 장사기록
>
> **떡볶이도 만들고,\
> 사이트도 만듭니다.**
>
> 안녕하세요. 가영이네 사장님, **박가영**입니다.\
> 엄마와 분식집을 운영하며 만난 작은 불편들을 AI와 함께 풀어봅니다.\
> 직접 만들고, 배우고, 고쳐가는 기록.

- 주요 버튼: `만든 사이트 보기` → 프로젝트 구역.
- 보조 이동: `박가영 소개` → 소개 구역.
- 오렌지는 핵심 단어·작은 그래픽·버튼에 집중한다.
- 영어 장식 문구는 보조로만 사용하며 한국어 설명을 우선한다.
- 초상 사진은 필수가 아니다. 제공받지 않은 실제 인물 사진이나 실제 가게 사진을 임의로 만들어 사용하지 않는다.

### 5.3 프로젝트 갤러리

섹션 제목은 **장사에서 시작한 것들.**로 한다.

데스크톱에서는 2열, 모바일에서는 1열로 배치한다. 캡처 높이가 달라도 화면을 억지로 잘라 동일한 높이로 만들지 않는다. 시각적인 읽기 순서와 문서·키보드 접근 순서가 일치하도록 구현한다.

**각 프로젝트 카드의 필수 순서**

| 순서 | 요소 | 요구사항 |
|---|---|---|
| 1 | 디자인 썸네일 | 프로젝트를 기억하게 하는 타이포그래피 중심 커버. 실제 화면과 구분되는 디자인 이미지 |
| 2 | 실제 사이트 캡처 | 썸네일 바로 아래 노출. 제목이나 긴 설명을 두 이미지 사이에 끼워 넣지 않는다. |
| 3 | 캡처 안내 | `실제 사이트 화면`과 함께 데모·로그인 등 필요한 상태를 짧게 표시 |
| 4 | 이름과 설명 | 프로젝트명, 1~2문장 설명, 간결한 분야 표시 |
| 5 | 이동 버튼 | `상세보기`, `실제 사이트 보기` |

썸네일을 눌렀을 때는 상세 페이지를 열고, 실제 캡처를 눌렀을 때는 확대 보기를 연다. 버튼과 이미지의 클릭 범위가 겹치지 않도록 구현한다.

### 5.4 짧은 자기소개

> **장사도, 배움도. 조금씩 앞으로.**
>
> 가영이네를 운영하는 박가영입니다.\
> 매장에서 떠오른 “이런 게 있으면 좋겠다”를 하나씩 직접 만들어 보고 있습니다.\
> 이곳에는 완성한 결과와 함께, 시도하고 고쳐가는 과정도 담습니다.

경력·수상·운영 성과는 확인된 자료가 있을 때만 추가한다. 장문의 이력서보다 실제 매장을 운영하는 사람의 관점이 드러나는 간단한 소개를 유지한다.

### 6.1 외국인 메뉴 도우미

- 실제 사이트: [Gayoungene Menu Finder](https://gayoungene-menu-finder.ghghgh0704.chatgpt.site).
- 출발점: 외국인 손님이 낯선 메뉴의 재료와 매운맛을 이해하고 선택하는 과정의 불편.
- 소개 범위: 다국어 메뉴 탐색, 피하고 싶은 재료와 매운맛·음식 종류를 기준으로 한 필터.
- 상태: **교육용 프로토타입 / 샘플 메뉴 8개**.
- 화면 캡처: 실제 메뉴 탐색 화면.
- 명시할 내용: 가격·재료·매운맛은 샘플 데이터이며 실제 주문·결제는 기존 매장 주문 수단에서 진행하는 구조.
- 표현 기준: 규칙 기반 탐색을 실시간 AI 추천으로 표현하지 않는다. 프로젝트 안의 AI 생성 인테리어 이미지를 실제 가게 사진으로 소개하지 않는다.

### 6.2 우리 가게 브랜드 도우미

- 실제 사이트: [브랜드 프롬프트 스튜디오](https://brand-prompt-studio.ghghgh0704.chatgpt.site).
- 출발점: 공지나 홍보물을 만들 때마다 매장 분위기와 문구 기준을 다시 설명해야 하는 불편.
- 소개 범위: 가게 정보를 정리하고 브랜드 가이드·콘텐츠 제작 프롬프트를 준비하는 흐름.
- 상태: **공개 프로토타입**. 세부 동작은 출시 전 현재 사이트와 대조한다.
- 화면 캡처: 브랜드 가이드·입력 흐름이 보이는 실제 화면.
- 명시할 내용: 준비한 프롬프트와 실제 자료를 개인 AI 도구에서 활용하는 방식. 사이트가 직접 이미지를 생성하거나 브랜드 데이터를 영구 저장한다고 단정하지 않는다.
- 기존 브랜드 관련 실험 사이트들은 이 프로젝트의 개선 과정으로 묶는다. 같은 목적의 버전을 별도 성과처럼 중복 나열하지 않는다.

## 7. 프로젝트 상세 페이지

프로젝트를 처음 보는 외식업 사장님도 이해할 수 있도록, 기술 설명보다 가게에서의 문제와 사용 장면을 먼저 설명한다.

| 순서 | 영역 | 내용 |
|---|---|---|
| 1 | 제목과 요약 | 프로젝트명, 짧은 설명, 분야, 현재 구현 상태 |
| 2 | 디자인 썸네일 | 홈에서 본 커버를 확장해 프로젝트의 시각적 연결 유지 |
| 3 | 실제 화면 | 대표 캡처를 바로 이어서 표시하고 필요한 추가 화면을 배치 |
| 4 | 왜 만들었나요? | 현장에서 느낀 문제와 만들기로 한 이유 |
| 5 | 이렇게 사용해요 | 확인된 기능을 기준으로 3~5단계의 쉬운 사용 흐름 |
| 6 | 어떻게 만들었나요? | 본인 역할, AI를 활용한 작업, 직접 검토·수정한 부분 |
| 7 | 지금 가능한 것 | 구현 기능, 데모 범위, 접근 조건 |
| 8 | 다음에 고칠 점 | 확인된 개선 계획. 이미 완료한 것과 분리 |
| 9 | 이동 | 실제 사이트 보기, 프로젝트 목록으로 돌아가기 |

제작 기간, 기술 스택, 사용 모델, 구현 상세는 확인된 값만 노출한다. 미확인 항목은 임의 값이나 빈 칸 표 대신 해당 항목을 생략하고 콘텐츠 관리 정보에 남긴다.

페이지 하단과 상단에서 목록으로 돌아갈 수 있게 한다. 브라우저 뒤로 가기 또는 목록 복귀 시 기존 프로젝트 위치로 돌아가는 동작을 지원한다.

## 8. 실제 화면 캡처 규칙

### 제작과 배치

- 실제 접속 또는 실제 실행에서 얻은 화면만 `실제 사이트 화면`으로 표시한다.
- 디자인 썸네일과 실제 화면 캡처를 **별도 이미지 자산**으로 관리한다.
- 캡처는 원본 종횡비를 유지한다. 늘이거나 압축하지 않는다.
- 불필요한 바깥 여백은 정리할 수 있으나 기능 설명에 필요한 UI와 상태 안내는 자르지 않는다.
- 길이가 긴 경우 대표 구간을 카드에 사용하고 전체 캡처 또는 추가 화면을 상세·확대에서 제공한다. 대표 구간이라는 안내 없이 전체 화면처럼 표시하지 않는다.
- 로그인, 데모 데이터, 오류 등 화면의 의미를 바꾸는 안내를 이미지 편집으로 지우지 않는다.
- 개인 정보·계정 정보가 있는 화면은 공개용 데이터로 다시 캡처하거나 해당 부분을 가린다.
- 공개용 이미지마다 실제 화면 이름, 접속 주소, 캡처 시점 또는 확인 시점을 콘텐츠 정보로 기록한다. 기존 캡처의 정확한 시점이 없으면 추정 날짜를 넣지 않는다.

### 확대 동작

- 캡처 선택 시 배경과 구분되는 확대 대화상자를 연다.
- `닫기` 버튼과 키보드 `Esc`를 지원한다.
- 확대 중 배경 페이지의 스크롤을 막고, 긴 이미지 자체는 스크롤해서 볼 수 있다.
- 키보드 초점은 대화상자 내부에 유지하고 닫으면 원래 캡처로 복귀한다.
- 모바일에서는 화면 안에 맞는 크기로 시작하고 긴 화면을 읽을 수 있게 한다.
- 이미지 로드 실패 시 `화면을 불러오지 못했어요`와 실제 사이트 이동을 제공한다.

## 9. 비주얼 디자인 시스템

### 9.1 색상

| 역할 | 기준 색상 | 적용 |
|---|---|---|
| 메인 포인트 | `#FF6600` | 주요 버튼, 강조 단어, 선택 상태, 작은 그래픽 |
| 블랙 | `#14140F` | 헤더, 푸터, 제목, 대비가 필요한 일부 커버 |
| 화이트 | `#FFFFFF` | 메인 배경, 갤러리, 넉넉한 여백 |
| 보조 배경 | `#F3F1EC` | 자기소개 등 화면 구역 구분 |
| 보조 텍스트 | `#65655F` | 설명, 분야, 캡처 안내 |
| 구분선 | `#DEDED8` | 카드 경계, 섹션 구분 |

화이트 60~70%, 블랙·짙은 글자와 영역 20~30%, 오렌지 약 10% 이내를 **초기 시각 조정 가이드**로 사용한다. 이는 참고 사이트에서 측정한 비율이나 픽셀 단위 합격 기준이 아니다. 확정된 A안의 인상과 각 화면의 가독성을 우선한다.

실제 프로젝트 캡처에는 해당 사이트의 원래 색을 유지한다. 오렌지를 맞추기 위해 캡처에 색상 필터를 씌우지 않는다. `#FF6600` 위 작은 버튼 글자는 짙은 색을 기본으로 하고, 모든 글자 조합의 명암 대비를 확인한다.

### 9.2 글자와 간격

- 한국어를 선명하게 표시하는 산세리프 글꼴을 사용한다. 프로토타입의 Noto Sans KR 계열을 기본 후보로 삼는다.
- 메인 문구는 굵게, 본문은 쉽게 읽히는 보통 굵기로 구분한다.
- 구현 시작값: 데스크톱 메인 문구 48~60px, 모바일 32~40px, 본문 16~18px.
- 본문 줄간격은 약 1.6배를 기본으로 한다.
- 메인 콘텐츠 최대 너비는 약 1,040~1,120px, 모바일 좌우 여백은 20~24px를 시작값으로 조정한다.
- 버튼은 최소 44px 높이의 조작 영역을 확보한다.
- 과도한 그라데이션, 그림자, 장식 효과는 사용하지 않고 이미지와 타이포그래피의 위계를 중심으로 구성한다.

위 수치는 구현 가이드이며 실제 한국어 줄바꿈과 캡처 크기를 보고 조정한다.

## 10. 반응형과 접근성

| 화면 너비 | 레이아웃 기준 |
|---|---|
| 320~599px | 프로젝트 1열, 소개문 자연스러운 줄바꿈, 캡처·버튼이 화면 안에 배치 |

- 링크·버튼·캡처 확대에 키보드 초점 표시와 의미 있는 이름을 제공한다.
- 실제 캡처에는 무엇을 보여주는지 설명하는 대체 텍스트를 제공한다.
- 일반 본문 명암 대비는 4.5:1 이상, 큰 글자는 3:1 이상을 목표로 검수한다.
- 장식용 움직임은 최소화하고 동작 감소 환경설정을 존중한다.

## 12. 구현·콘텐츠 관리 기준

특정 프레임워크는 아직 확정하지 않는다. 초기에는 별도 서버·회원 시스템 없이 운영할 수 있는 정적 콘텐츠 중심 구성을 우선 검토한다. 프로젝트별 데이터와 화면 컴포넌트를 분리해 다음 사례를 쉽게 추가할 수 있게 한다.

### 프로젝트별 관리 항목

| 필드 | 내용 |
|---|---|
| 식별자·주소 | 프로젝트 ID, 상세 slug, 실제 사이트 URL |
| 기본 소개 | 제목, 카드 설명, 분야, 목록 순서 |
| 이미지 | 디자인 커버, 실제 캡처 목록, 대체 텍스트, 캡처 설명 |
| 상세 내용 | 문제, 목적, 사용 흐름, 본인 역할, AI 활용 과정, 개선점 |
| 상태 | 데모·샘플·로그인 필요 등 사용자에게 보여줄 설명 |
| 사실 확인 | 기능별 확인 내용, 참고 자료, 확인 시점, 미확인 항목 |

### 이미지·속도

- 고해상도 원본과 화면 표시용 최적화 이미지를 구분한다.
- 실제 화면의 작은 글자가 뭉개지지 않는 범위에서 이미지 크기를 최적화한다.
- 이미지의 너비·높이 또는 종횡비를 미리 지정해 로딩 중 레이아웃 이동을 줄인다.
- 화면 아래 캡처는 지연 로딩한다.
- 프로토타입의 이미지를 한 HTML에 모두 넣는 방식은 최종 구현의 필수 조건이 아니다. 운영 버전에서는 개별 자산과 적절한 크기별 이미지를 우선한다.
